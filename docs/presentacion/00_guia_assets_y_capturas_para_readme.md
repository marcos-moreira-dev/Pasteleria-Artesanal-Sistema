# Guía De Assets Y Capturas Para README

## Objetivo

Preparar la futura versión propagandística del repositorio sin improvisar capturas, nombres o estructura visual.

## Estructura sugerida

```text
assets-readme/
  logo/
    logo-principal-placeholder.md
  capturas/
    01-landing-home-placeholder.md
    02-catalogo-placeholder.md
    03-contacto-placeholder.md
    04-admin-dashboard-placeholder.md
    05-admin-clientes-placeholder.md
    06-admin-pedidos-placeholder.md
    07-admin-produccion-placeholder.md
```

## Convención de capturas

- `01-landing-home`
- `02-catalogo`
- `03-contacto`
- `04-admin-dashboard`
- `05-admin-clientes`
- `06-admin-pedidos`
- `07-admin-produccion`

## Contenido mínimo de cada placeholder sidecar

- nombre del asset
- ruta esperada
- propósito narrativo en el README
- estado del asset
- prompt de generación si aplica
- nota de reemplazo posterior

## Criterio visual

- las capturas deben mostrar producto funcionando
- si hay placeholders visuales, deben ser coherentes con la escena
- no usar capturas de código como reemplazo de interfaz
- no mezclar tema de negocio con infraestructura en la portada

## Recordatorio

El README final debe vender `la experiencia de una pastelería organizada`, no `el stack técnico`.
